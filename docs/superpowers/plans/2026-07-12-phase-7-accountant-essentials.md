### Task 1: Sub-accounts (hierarchical chart of accounts)

Add parent/child accounts with leaf-only posting, and roll them up in the core reports. Migration on `accounts`: `parent_id` (self-FK, restrictOnDelete, nullable), `is_postable` bool (default true; EXPLICIT, not derived from "has children"), `depth` unsignedTinyInteger default 0, `path` string (materialized ancestor path e.g. `/12/152/`, indexed). Backfill: every existing account → top-level postable leaf (`parent_id=NULL, is_postable=true, depth=0, path='/{id}/'`) — zero data movement, existing lines still valid. **Leaf-only posting enforced THREE ways:** (1) LedgerService::validate rejects a LineDraft whose account `is_postable=false` (a new domain exception); (2) a DB CHECK/trigger is impractical cross-db — instead an IntegrityChecker rule "no journal_line points at a non-postable account" (fail loud); (3) a CI/feature test. **Promotion:** a service `AccountService::makeParent(Account $leaf)` — when a posted leaf gains children, auto-create a child `"<name> — Other"` leaf, move its existing journal_lines to the child in one transaction (this is a ledger MOVE, not a re-post — the lines' account_id changes; guard: only allowed via this method, audited), then set the parent is_postable=false. Model: Account gains parent()/children()/descendants scopes + a rollup helper. Validations: child shares parent's root type + subtype family (block expense under asset); cap depth ≤5; opening balances/postings only on leaves; moving a subtree updates path+depth for ALL descendants in one txn. **Roll up in reports:** TrialBalanceReport, BalanceSheetReport, ProfitAndLossReport, GeneralLedgerReport must show leaf rows + parent subtotal rows, indented by depth, ordered by path (parent total = Σ descendant leaves via `path LIKE '/12/%'`; sign-flip at render by root type). CoA UI (Accounts/Index): a tree with expand/collapse, "add sub-account" action, and the parent/child indentation. Gate account.manage as today.
**Tests:** migration backfills existing accounts as top-level leaves (existing balances byte-identical — assert a full trial balance before/after migration is unchanged); posting to a non-postable parent → rejected (LedgerService + integrity rule); rollup: a parent with 2 posting children shows each child + the correct parent subtotal in TB/BS/P&L; promotion moves lines to the "— Other" child and flips the parent (audited, balances unchanged); depth cap + cross-type nesting rejected; subtree move updates all descendants' path/depth; a company with NO sub-accounts renders reports exactly as before (regression). Mirror: Account model + LedgerService + the Phase-5 report services.

### Task 2: Activate/deactivate — surfaced everywhere

Make archive/unarchive first-class and consistent across accounts, contacts, and items (accounts already have archiving; extend + surface). Ensure `archived_at` (or the existing is_archived) on: accounts (have), contacts, items. Behaviour: archived records are HIDDEN from all pickers/dropdowns (invoice/bill/expense/payment forms, category pickers) but RETAINED in history and historical reports; an archived account/contact/item can't be selected for a NEW transaction but its past transactions and balances remain. UI: an Active/Archived filter on the Accounts, Contacts, and Items list screens + an Archive/Restore action (gated appropriately). Guard: cannot archive an account that is a non-postable parent with active children (offer cascade or block); cannot archive a system account; archiving never touches posted data.
**Tests:** archiving a contact/item/account hides it from the relevant pickers but keeps it in lists (Archived filter) and in historical reports; restore works; a NEW invoice/bill/expense can't select an archived contact/category (422); system accounts can't be archived; archiving doesn't alter any balance; gated + audit-logged. Mirror: existing accounts archiving + the list-screen filter pattern.

### Task 4: Statement of Cash Flows (indirect method)

The third core statement, built per spec seed §2. Add `cf_class` to accounts (enum: operating / investing / financing / cash / excluded, nullable — defaults derived from account type/subtype where unambiguous; seed the standard chart's classification; editable by an accountant). `app/Services/Reports/CashFlowReport.php` implementing BOTH engines: (A) cash-leg direct classification (classify each cash-account line by the nature of the other legs in its entry; transfers between two cash accounts net to zero); (B) indirect presentation (NI + non-cash add-backs ± working-capital deltas). **The depreciation add-back is sourced from the depreciation EXPENSE account, never accumulated-depreciation's movement; investing proceeds/purchases from the actual cash legs.** Ship the SIX exact-integer assertions as tests: (1) Σdebit==Σcredit in-period; (2) CFO+CFI+CFF+FX_on_cash == closing−opening cash; (3) CFO_indirect==CFO_direct; (4) SCF opening/closing cash == Balance-Sheet cash at both dates; (5) every cash line classified (unclassified=0, else a loud finding); (6) no add-back sourced from a contra/mixed account. Handle: opening entries dated ≤ from−1 excluded from the period; unrealized FX on foreign cash → separate "effect of FX on cash" line; retained_earnings split (NI at top, dividends in Financing) — never use RE raw movement. Controller + Reports/CashFlow.tsx (period picker, Operating/Investing/Financing sections, the reconciliation-to-cash check shown, CSV, print, tokens only, no debit/credit words — it's a statement). Add to Reports nav + the accountant package. Interest/dividend placement + cash-pool boundary are config with sensible defaults (documented; confirm-with-accountant later).
**Tests (the assertions ARE the gate):** a company with invoices+payments+expenses+a depreciation-style manual JE+an asset purchase → SCF ties out (all 6 assertions); CFO_indirect==CFO_direct on a mixed period; depreciation add-back uses the expense account (assert it's NOT accumulated-depreciation movement); a transfer between two bank accounts nets to zero in the SCF; SCF cash == Balance Sheet cash at both ends; empty company → all zeros, balanced; a foreign-currency payment's FX shows on the FX-on-cash line. Mirror: LedgerBalances + BalanceSheetReport + the §2 algorithm.
